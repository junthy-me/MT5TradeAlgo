## Context

当前 `PriorMove` 前置条件以 `(a + b1)` 作为结构分母，代码和主 spec 也已经按这个口径实现与描述。该规则用于把 `Pre0->P0` 的方向性 move 归一化为“相对结构比例”，因此分母定义会直接影响候选是否通过前置条件。

这次改动不引入新规则，也不改变 `Pre0` 搜索、方向极值约束、最小间隔或 strongest `Pre0` 选择逻辑，只调整比例归一化时使用的结构尺度。

## Goals / Non-Goals

**Goals:**
- 将 `PriorMove` 最小 move 比例的结构分母统一改为 `a + b1 + b2`。
- 让主 spec、change spec、README 和实现口径一致。
- 保持多头/空头镜像逻辑和现有日志字段含义不变，仅改变阈值计算结果。

**Non-Goals:**
- 不修改 `PriorMove` 的启停开关、lookback 窗口或最小 bar 间隔。
- 不调整 `a`、`b1`、`b2` 的结构定义方式。
- 不改变 `BOTH/LONG_ONLY/SHORT_ONLY` 的候选选择策略。

## Decisions

### 决策：将结构分母扩展为 `a + b1 + b2`

`PriorMove` 的门槛本质上是“前置 move 相对于当前结构的最小比例”。既然当前结构在后续规则和日志里已经包含 `a`、`b1`、`b2` 三段，分母只使用 `a + b1` 会系统性低估结构尺度。改为 `a + b1 + b2` 可以让前置条件门槛和完整结构长度保持一致。

备选方案：
- 保持 `(a + b1)` 不变：实现简单，但继续保留当前结构尺度偏小的问题。
- 改成其他组合如 `a + b2`：缺少和现有结构拆分的一致性，也没有明确业务依据。

### 决策：只修改阈值计算，不改日志字段与判定流程

当前日志和排障已经围绕 `pre0Move`、`minRequiredMove`、`structureValue` 建立。为了减少变更面，这次只修改 `structureValue` 的构成，不新增字段，也不改规则执行顺序。这样可以把影响面收敛到公式本身，便于后续用同一套日志做对比验证。

备选方案：
- 引入新的日志字段专门区分旧分母与新分母：可观测性更强，但会扩大改动面，不适合这次窄改。

## Risks / Trade-offs

- [更多候选会被前置条件拦截] → 分母变大后，达到同一最小比例所需的 `Pre0->P0` move 更大，历史触发频率可能下降。通过更新 spec 和 README 明确这是预期行为。
- [实现和文档口径再次漂移] → 同步修改主 spec、change spec 和 README，并在实现时只保留一个 `structureValue` 计算来源。
- [回测对比不易理解] → 保持日志字段名不变，只让 `minRequiredMove` 数值随新分母变化，便于直接对比前后 run。
