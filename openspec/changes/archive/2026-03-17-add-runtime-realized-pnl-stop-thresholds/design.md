## Context

当前策略只维护单笔持仓层面的强止损、弱止损、唯一止盈和观察窗口，没有“本次运行内累计已实现盈亏达到阈值后停止继续开新仓”的全局门控。现有 `BacktestSummaryState` 主要服务 tester 结束时的点数级 summary，既不是运行时门控状态，也不按账户货币金额驱动开仓停止。

这次改动需要跨越运行时输入、平仓统计、开仓门控和日志摘要四个位置，但不改变既有持仓的出场管理流程。

## Goals / Non-Goals

**Goals:**
- 增加最大盈利停止阈值和最大亏损停止阈值输入项。
- 以本 EA 已闭仓交易的账户货币已实现金额作为唯一统计依据。
- 达到任一阈值后，停止新的自动开仓，但继续管理已有仓位直到它们正常出场。
- 在停止触发时打印一次原因日志和一次摘要日志。

**Non-Goals:**
- 不把浮盈浮亏纳入阈值统计。
- 不在触发阈值后强制平掉现有持仓。
- 不跨 EA 重启或终端重启持久化 stop 状态。
- 不把这套逻辑做成按 symbol 独立门控；范围保持在整个 EA 实例。

## Decisions

### 决策：金额统计以已闭仓交易的真实账户货币结果为准

运行期 stop 的判断目标是“本 EA 实际已经赚到或亏掉多少钱”，因此统计口径应当来自已关闭交易的真实已实现结果，而不是用开平仓价差自行推导的理论金额。设计上应按本 EA 自己的已关闭交易累计：
- `grossProfitMoney`
- `grossLossMoney`
- `netRealizedMoney = grossProfitMoney - grossLossMoney`

该金额口径应包含真实已实现结果中的盈利/亏损，并以账户货币计量；实现时应优先复用 MT5 关闭交易后的真实结果来源，而不是仅复用现有的 `pnlPoints`。

备选方案：
- 仅用价格差换算金额：实现简单，但会偏离真实已实现收益。
- 直接用账户余额变化：会混入手工单、其他 EA 或外部资金变动，不适合作为本 EA 门控依据。

### 决策：达到阈值后只禁止新开仓，不影响已有持仓管理

用户已经明确 stop 的目的在于防止继续新增风险，而不是粗暴中断已有仓位。因此门控应当挂在“新开仓”路径上，而 `ManageOpenPositions()`、强止损、弱止损、止盈和观察窗口逻辑保持不变。

实现上，流程应当保持：
- 先管理已有持仓
- 再检查是否已进入 runtime-stopped 状态
- 如果已停止，则直接跳过新的 pattern 检测/开仓

### 决策：阈值为 0 表示禁用，对应 stop 状态本次运行内不可恢复

为了兼顾灵活性和安全性：
- `InpMaxProfitStopMoney = 0` 表示禁用最大盈利停止
- `InpMaxLossStopMoney = 0` 表示禁用最大亏损停止

一旦任一阈值触发，stop 状态在本次 EA 运行内保持有效，不自动恢复，也不因后续已有仓位平仓而重新允许开仓。重启 EA 后重新开始累计。

### 决策：运行时停止摘要单独记录，不复用 tester-only backtest summary 语义

现有 `回测总结` spec 明确限定为 tester-only。为了避免把 live/runtime stop 和 tester 末尾 summary 混在一起，本次新增的停止日志应当是独立的 runtime stop event 和 runtime stop summary，而不是修改 tester-only summary 的触发语义。

## Risks / Trade-offs

- [金额来源不准确会导致 stop 误触发或漏触发] → 约束实现必须基于本 EA 已闭仓交易的真实已实现账户货币结果。
- [全局 stop 可能让某个 symbol 的亏损阻断其他 symbol 的后续机会] → 这是有意为之，语义定义为“停止本次算法自动交易”，不是单品种风控。
- [停止后日志刷屏] → 运行时 stop 原因日志和摘要日志都只打印一次，其后只保留已有持仓的正常 `EXIT` 日志。
- [与现有 tester summary 概念混淆] → 保持 tester-only summary 不变，runtime stop 采用独立事件名和摘要字段。
